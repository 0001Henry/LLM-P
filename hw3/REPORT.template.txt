高效率的 BERT 模型古文断句标点
《大语言模型与应用实践》HW3 实验报告

摘　要

针对无标点文本的自动断句与标点恢复问题，本实验完成预训练 BERT 模型微调和长文本批量推理两个任务。首先，利用人民日报 1998 年 1 月语料，将标点恢复转化为字符级序列标注任务，在中文 BERT 上训练八分类标点预测器。其次，针对 BERT 上下文长度限制及传统滑窗的串行依赖，采用固定重叠窗口、批量前向计算和中心加权概率融合，实现长文本连续标注。

本次实验使用 $train_paragraphs 个训练段落进行 $epochs 轮部分参数微调，在独立新闻测试子集上取得标点 micro-F1 为 $test_f1、断点 F1 为 $boundary_f1 的结果。在本机 Apple GPU 上，4,000 字长文本的批量推理相对于串行句号截断基线实现 $overall_speedup 倍加速，相对于相同固定窗口的单窗口推理实现 $batch_speedup 倍加速。五段古文示例的标点 micro-F1 为 $ancient_f1，表明新闻语料训练所得能力向古文迁移时仍存在明显局限。

关键词：BERT；标点恢复；序列标注；滑动窗口；批量推理


1　实验目的与任务划分

本实验依据课程课件《2026-秋季-大语言模型与应用实践-L2-part2》第 68 页的编程练习开展。实验重点是现有预训练模型的微调应用及长文本处理效率，不涉及从零预训练 BERT。

任务一：利用现成的带标点语料构造监督数据，微调预训练中文 BERT，获得能够对无标点文本进行断句和标点恢复的模型，并完成训练、验证与独立测试。

任务二：针对古文段落可能超过 BERT 的 512-token 上下文上限，设计可采用 Batch 解码的长文本处理方法。通过与课件给出的串行滑窗思路对比，评估处理效率及输出质量。

两个任务共享同一个微调后的模型。任务一关注标点预测能力，任务二关注在模型不变的条件下如何组织窗口、执行推理并合并结果。本文分别呈现两项任务的方法和实测结果。

2.2　数据来源与清洗

数据来自课程随附的“1998-上半年-带音(1).rar”，仅使用其中“1998-01-2003版-带音.txt”。原始文件采用 GB18030 编码，包含段落编号、分词空格及形如 {shang5} 的读音注释。

数据制备步骤如下：
（1）解析段落编号，以编号前三部分作为文章 ID。例如，19980101-01-001-007 对应文章 19980101-01-001。
（2）移除编号、分词空格及花括号中的读音注释。
（3）扫描带标点文本，将目标标点转为前一字符的监督标签，再从输入中移除标点，得到等长的字符序列和标签序列。
（4）将英文逗号、句点、问号、叹号、分号和冒号归一化为对应中文标点。连续出现的目标标点取最后一个；不属于目标集合的 Unicode 标点及空白被删除。
（5）按清洗后的无标点文本全局去重，过滤不足 10 个字符的段落。符合长度要求但不含目标标点的段落仍予保留。

该清洗策略适用于本次汉字主体语料，但不会恢复引号、括号、破折号、省略号或原始排版；对小数点等具有其他含义的符号也未进行专门消歧。这是标签设计和数据处理的适用边界。

3　任务一：基于预训练 BERT 的标点模型微调

3.1　任务形式化与标签定义

设清洗后的输入字符序列为 X=(x₁,…,xₙ)，模型对每个字符预测其后的标点标签 yᵢ。标签集合为：

Y={O，逗号，句号，问号，叹号，分号，冒号，顿号}。

例如，“学而时习之，不亦说乎？”被转换为输入“学而时习之不亦说乎”，其中“之”后的标签为逗号，“乎”后的标签为问号，其余位置为 O。推理时依次输出原字符及其预测标点，即可重建标点文本。标签从原始语料自动生成，不将目标标点保留在模型输入中。

3.2　字符与模型输入的对齐

本实验采用逐字符查询 BERT 词表的输入方式，确保一个 Unicode 字符对应一个模型位置。英文字符按小写形式查询词表，不在词表中的字符使用 [UNK]；输出重建时仍保留原字符。

这一设计避免了常规 WordPiece 分词后需要额外处理子词与字符标签对齐的问题，但对英文长词、罕见古字和非汉字符的表示较为简化。它是本实验针对中文标点恢复作出的工程取舍，并非通用分词方案。

每个窗口首尾加入 [CLS] 和 [SEP]。推理窗口含 400 个正文字符时，实际输入为 402 个 token，未超过 512-token 限制。代码将正文窗口最大长度限制为 510。Batch 内按实际最长序列补齐，并使用 attention mask 屏蔽 padding。

3.3　模型结构与训练目标

模型以 google-bert/bert-base-chinese 的预训练权重初始化 BERT 编码器，使用 BertForTokenClassification 在各位置的上下文表示上执行标点分类。编码器输出经 dropout 和线性分类层得到八类 logits，再通过 softmax 得到概率：

hᵢ = BERT(X)ᵢ
pᵢ = softmax(W·dropout(hᵢ)+b)

损失函数为有效字符位置上的平均交叉熵：

L = −(1/|V|) Σᵢ∈V log pᵢ(yᵢ)

其中 V 为正文有效位置集合。[CLS]、[SEP] 和 padding 的训练标签均为 −100，不计入损失。新增分类头随机初始化，BERT 编码器加载预训练参数，因此本实验属于下游微调，而非随机初始化整个模型后训练。

4　任务二：长文本的高效率 Batch 推理

4.1　串行句号截断基线

按照课件给出的基础思路，每次从当前位置取最多 400 个字符输入模型。对于非尾窗，在前 300 个字符的预测结果中寻找最后一个句号，输出至该句号对应的字符，并将其后的位置作为新起点；若前 300 字没有句号，则固定前进 300 字。最后一个窗口输出全部剩余结果。

该方法能够处理超过模型上下文上限的文本，但下一窗口起点取决于上一窗口的预测，无法在推理前确定同一篇文本的全部窗口。窗口间依赖限制了批量处理能力。无句号时采用固定前进策略，是防止算法停滞的必要边界处理。

4.2　固定重叠窗口与批量前向计算

改进方法将窗口位置与预测结果解耦。对于长度为 N 的文本，按窗口长度 W=400、步长 S=300 预先构建窗口，相邻完整窗口重叠 100 字。窗口到达文本末尾后停止，不再生成冗余尾窗。

将最多 B=8 个窗口组成一个批次，执行一次模型前向计算。推理时使用 eval 模式关闭 dropout，并使用 inference_mode 关闭梯度记录。各窗口的有效字符概率按原文偏移量映射回全局位置，不在窗口边缘强制添加句号。

该方案的重点不是扩大 BERT 的上下文长度，而是将多个符合上下文限制的窗口组织为可以并行计算的批次。

4.3　重叠区域的加权概率融合

同一字符可能被多个窗口覆盖。考虑到窗口边缘的可用上下文较少，采用中心权重大、边缘权重小的融合方式。对于长度为 L 的窗口，局部第 i 个位置（从 0 开始）的权重为：

w(i)=min(i+1,L−i)。

设 pₖ(j,c) 为第 k 个窗口对全局位置 j 的类别 c 的预测概率，Ω(j) 为覆盖 j 的窗口集合，则融合概率及最终标签为：

P(j,c)=Σₖ∈Ω(j) wₖ(j)·pₖ(j,c) / Σₖ∈Ω(j) wₖ(j)
ŷⱼ=argmax_c P(j,c)。

融合采用概率而非已离散化的标签，以保留各窗口对不同类别的相对置信信息。最终按全局位置解码，每个字符只输出一次。窗口覆盖保证分母大于零，短文本、非整窗尾部及无句号长文均可使用同一流程处理。

算法步骤如下：
1. 清洗输入文本，保留待预测的字符序列。
2. 根据 W、S 生成全部固定窗口及全局起止位置。
3. 初始化逐字符的八类加权概率累加器及权重累加器。
4. 每次取最多 B 个窗口，补齐、构造 mask 并执行模型前向计算。
5. 将各窗口有效字符的 softmax 概率按位置和中心权重累加。
6. 对累加概率归一化并取 argmax，按字符顺序恢复标点。

4.4　效率与空间开销分析

当 N>0 时，固定窗口数 K=1+ceil(max(0,N−W)/S)。单窗口推理需要 K 次模型调用，批量推理需要 ceil(K/B) 次。对于本次 4,000 字输入，固定窗口共 13 个，B=8 时只需两次模型调用。

批量处理减少了调用与调度次数，并提高了同一批次内的设备并行利用率，但不会消除重叠字符的计算。对于远长于窗口的文本，正文 token 处理量约为 N·W/S，本实验 W/S=4/3；固定模型与窗口长度时，总计算量仍随文本长度增长。自注意力还包含与窗口长度平方相关的计算，因此不能通过无限增大窗口来替代合理的批量调度。

当前实现保存 N×8 的 float32 概率累加器和 N 个 float32 权重，二者合计约 36N 字节，不含模型、批次中间张量及临时数组。批次显存需求随 B 增加。对于书籍级文本，可进一步实现已完成覆盖位置的流式输出，以降低全局缓存需求；该扩展尚未纳入本次实现。


5　评价指标与实验协议

5.1　标点恢复指标

标点 micro-Precision、micro-Recall 和 micro-F1 只统计非 O 标签。只有标点位置与类别均正确才计为 TP；错误插入或预测成错误标点计入 FP；漏标或类型错误计入 FN。类型误判会同时贡献一个 FP 和一个 FN。计算公式为：

Precision=TP/(TP+FP)，Recall=TP/(TP+FN)
F1=2·Precision·Recall/(Precision+Recall)。

断点指标将七种目标标点合并为“有标点”一类，只检查位置，不区分类别。它并不只评价句号或句末边界。另报告各类标点的 P/R/F1 和字符准确率。分母为零时，程序将对应指标记为 0；因此必须结合类别支持数解释零值。

5.2　效率对比协议

效率实验使用同一微调 checkpoint，将固定抽样的测试段落依次拼接并截取前 4,000 字，对比三种方法：串行句号截断、固定窗口 B=1、固定窗口 B=8。

计时前先对一个窗口预热，计时起止点同步设备，分别重复三次并取中位数。计时范围包括输入词表映射、批次构造、设备传输、模型前向计算和预测融合，不包含模型加载、数据集读取及指标计算。各方法按照上述固定顺序执行，本实验未进行运行顺序随机化或置信区间估计。

固定窗口 B=1 与 B=8 使用相同窗口及融合策略，是隔离 batch 因素的受控对比。串行基线会改变窗口位置及上下文，因此它与改进方案的精度差异不能仅归因于 batch。拼接段落不一定来自相邻文章，该输入用于验证长文本处理流程，不等同于连续古文篇章。

本次实验记录中，13 项自动化测试全部通过。测试涵盖语料注释清洗、字符标签对齐、空文本、非法窗口参数、多种长度的窗口覆盖、无句号串行前进、重叠权重融合、不同 Batch 的预测一致性，以及训练、验证、测试之间的文章与文本去重检查。

另使用随机初始化的微型 BERT 执行输入对齐与反向传播集成测试。该微型模型仅用于测试张量形状和梯度流程，不参与本文训练实验或性能评价；所有实验结果均来自加载预训练中文 BERT 后微调的模型。

结果文件保留了训练参数、逐轮验证结果、测试指标、三次测速原始时间、模型环境与古文预测。报告中的数值由这些本地结果文件生成，而非根据理论调用次数推算。重新生成报告无需重新训练模型。


8　局限性与改进方向

（1）数据规模与训练范围。本次使用子集进行三轮训练，并冻结了大部分编码层。实验验证了端到端流程，但没有完成全量语料训练或所有参数的充分优化。

（2）领域差异。现代新闻与古文在词义、句法和标点习惯上存在差异。新闻测试指标不能解释为古文准确率，后续应引入独立的古文训练及测试数据。

（3）标签范围与输入表示。当前只恢复七类标点，且逐字符词表映射可能弱化英文词和罕见古字的表示。可进一步研究更完整的标点体系与严格对齐的子词编码。

（4）长度与融合策略。训练正文窗口为 128 字，推理窗口为 400 字，存在长度分布差异。中心加权融合是一种工程启发式，本文没有与均匀融合或仅取中心区域等方法进行消融比较，不能断言它是最优方案。

（5）性能评价范围。本次仅在一台 Apple M4 设备、一个 4,000 字拼接输入上比较 B=1 和 B=8，没有测量峰值显存，也没有完成不同长度和不同硬件下的系统性评测。后续可扩展 batch、步长及设备组合，并采用更多文本和重复实验评估稳定性。

（6）类别不均衡。少数标点表现较弱，可在独立验证集上比较类别加权损失、样本重采样或增加稀有类别样本，但需防止以测试结果反复调整超参数。


9　结论

本实验完成了预训练 BERT 标点模型的微调、验证、测试及长文本批量推理两个任务。在模型层面，字符级序列标注实现了从现有带标点语料自动构建监督数据，并获得可用于无标点文本预测的模型。在工程层面，通过将窗口位置固定化，消除了串行句号截断对前一窗口预测的依赖，再通过 Batch 前向计算与全局概率融合恢复连续输出。

实际新闻测试子集上的标点 F1 为 $test_f1，断点 F1 为 $boundary_f1；长文本批量方案相对串行基线取得 $overall_speedup 倍加速，相对相同固定窗口的单窗口执行取得 $batch_speedup 倍加速。结果支持该方案在本实验条件下具有实际效率收益，同时也表明现代新闻语料训练的标点模型在古文应用中仍需进一步进行领域适配。

附录 B　环境准备与复现步骤

以下命令均在 hw3 目录下执行。首次运行需能够访问模型下载地址。预训练权重约 400 MB，环境、数据和模型合计需预留数 GB 空间。模型下载先写入临时文件，完整下载后再改名；连接失败后可重试。

B.1　创建独立环境并准备语料

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-lock.txt
mkdir -p data/raw
bsdtar -xf '../1998-上半年-带音(1).rar' -C data/raw '1998-上半年-带音/1998-01-2003版-带音.txt'
python prepare.py
python download_model.py
python -m unittest discover -v

requirements-lock.txt 用于重建本次依赖版本；其他平台如无法安装其中的特定版本，可使用 requirements.txt，并在新实验中记录实际环境。固定随机种子有助于复现数据抽样，但不同硬件或库版本下不保证逐位相同的训练结果。

B.2　复现本次实验规模

python run_experiment.py

该入口依次运行测试、1,000 段三轮微调、独立测试、4,000 字测速、古文示例预测及报告生成，覆盖两个任务的实际实验流程。重新运行会更新模型及同名结果文件，如需比较多组实验，应事先保留现有结果。

对应的主要训练与测速命令为：

python bert_punct.py train --train-limit 1000 --eval-limit 100 --epochs 3 --freeze-layers 10 --batch 8
python bert_punct.py benchmark --model models/punctuation --eval-limit 100 --chars 4000 --batch 8 --repeats 3

B.3　使用已保存模型进行预测

python bert_punct.py predict --model models/punctuation --text '学而时习之不亦说乎有朋自远方来不亦乐乎'
python bert_punct.py predict --model models/punctuation --input ancient.txt

ancient.txt 应为 UTF-8 编码文本，预测输出保存于 results/prediction.txt。输入中已有的标点和空白按同一清洗规则处理，输出不保留原始排版。

B.4　独立评估与重新生成报告

python bert_punct.py evaluate --model models/punctuation --eval-limit 100
python make_report.py

evaluate 使用固定种子抽取的测试子集。make_report.py 只读取现有实验结果及报告模板，不重新训练。若改变实验配置，应同步调整模板中对实验设置的文字说明。

B.5　全量扩展实验（本文未执行）

python bert_punct.py train --epochs 3 --batch 8
python bert_punct.py evaluate --model models/punctuation

默认 train-limit 和 eval-limit 为 0，表示使用完整的对应数据集；freeze-layers 为 0，表示更新全部 BERT 参数。也可调整 train-window、window 和 stride，但需满足正文窗口不超过 510，且 0<stride≤window。设备内存不足时应减小 batch；程序不会自动改变窗口长度以掩盖内存不足。
